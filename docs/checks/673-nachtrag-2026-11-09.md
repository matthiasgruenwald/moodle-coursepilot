Einordnung:

- **`retention.php:147/151`, `xml_activity_creator.php:205`:** `LogicalAndNegation`/`LogicalAnd` kehren die Schleifenbedingung um (`while (a && b)` wird `while (!(a && b))`, bzw. `walk()` läuft ohne Abbruchbedingung). Das sind **Endlosschleifen** (Zeit-/Speichergrenze). Im Volllauf endete der Prozess ohne PHPUnit-Ausgabe (`errored`), im Einzellauf wertet Infection sie als Timeout. Beides zählt als erkannt; ein Test, der die Schleife begrenzt, würde nichts beweisen. Kein Handlungsbedarf.
- **`connection.php` (Zeilen 158, 386–449):** Im Einzellauf kein Abbruch. Die Mutanten werden mit echten Assertions getötet (`authenticate_access_token`, `access_error`, Lock-/Rotationspfad). Die Abbrüche im Volllauf waren damit **Lastartefakte** des Abschnitts `classes-01` (11.525 s, Watchdog beendete hängende Mutanten-Prozesse), keine Eigenschaft des Codes oder der Tests. Der Mutant `update_question_category.php:219` bleibt wie im Hauptbericht als Endlosschleife erkannt.
- Grenze: Die Neumessung nutzte eine `junit.xml`-Kopie von der Hauptinstanz mit neu gesetztem Änderungsdatum (die Quellen wurden seit dem Coverage-Lauf in den drei Dateien nicht geändert; der Frischeprüfung des Läufers genügte das Datum nicht, weil ein neuer Checkout neuere Zeitstempel trägt).

## 150 „nicht zugeordnete“ Mutanten: Ursache geklärt, kein Defekt

Aus den Rohberichten (`processOutput` der 153 Treffer mit `OK, but there were issues`): Die Warnung kommt **vom Mutanten selbst**, nicht vom Test. Der mutierte Code löst eine PHP-Warnung aus (z. B. `Undefined array key "approved"` in `glossary_entry_writer.php:172`, `Undefined array key "sectionnum"` in `history/version_restore.php:240`, `foreach() argument must be of type array|object, true given` in `question_import.php:545`, `Attempt to read property "expires" on false` in `connection.php:86`). PHPUnit meldet den Lauf trotz bestandener Assertions mit Exitcode ≠ 0 (Warnung), Infection wertet das als getötet. Die Warnung steht beim ungemutierten Code nicht an dieser Stelle; das Gate ist mit denselben Tests grün.

Bewertung: Das Verhalten ist **beobachtbar** (der Mutant erzeugt eine Warnung, die jeden Gate-Lauf rot färbt), aber **keine Assertion benennt es**. Die Mutanten sind deshalb kein Fehler im MSI, nur schwächer belegt. Behoben wird das nicht pauschal: Pro Stelle eine zusätzliche Assertion wäre Testarbeit ohne Gate-Nutzen, die Kill-Qualität zeigt der Prune-Bericht. Der MSI bleibt als konservativer Trendwert wie im Hauptbericht (92,27 %; ohne diese 150: 91,12 %).
