## L615 (`lock_connection`, `'id' => $id` entfernt) – Bewertung Phase 1 (überholt durch Phase 2)

Quelle `connection.php:603–616`: `UPDATE … SET statehash = :marker WHERE id = :id AND revoked = 0`, dann `record_exists(GRANT, ['id'=>$id,'statehash'=>$marker,'revoked'=>0])`. Aufrufer: `rotate_refresh_token` (L157) und `revoke_token` (L525). Der vorhandene Ignore nennt „Probabilistic equivalence“ (256-Bit-Kollision), ausdrücklich „not a logical proof“.

Befund aus der Messung: **Der Mutant ist nicht logisch äquivalent, sondern mit dem vorhandenen Test-Override tötbar.** Voraussetzung ist nur, dass eine andere aktive Zeile (`revoked = 0`) denselben Marker trägt und das Ziel-Grant nicht aktualisiert wird (`revoked = 1`). Dann liefert das Original `false`, der Mutant `true` und `rotate_refresh_token` läuft weiter (Token-Ausgabe für ein widerrufenes Grant). Im Betrieb ist das nur bei Marker-Kollision zweier `random_bytes(32)` möglich – die Produktions-Äquivalenz ist daher tatsächlich nur probabilistisch (Risiko ≈ 2⁻²⁵⁶, plus Annahme eines fehlerfreien CSPRNG; ein Fehler im Zufallsgenerator würde weder Mutant noch Original unterscheiden helfen). Das ist eine begründete, aber **keine bewiesene** Äquivalenz.

Experiment (ohne Repo-Änderung; Test nur in den s1-Mount kopiert und danach per `sync-plugin.sh` zurückgesetzt, `diff -r` = identisch): `exp615.log`
