Architecture and contributing

For you if you build similar Moodle AI tools or want to contribute. Source of the server MCP: Plugin/src/local_coursepilot/.

Principle: the plugin is the MCP endpoint

Coursepilot is a local Moodle plugin that acts as an MCP server itself. The AI client speaks Streamable HTTP with /local/coursepilot/mcp.php; nothing runs on the teacher's computer.

Open the architecture diagram (interactive, English labels)

AI client --HTTPS + OAuth--> mcp.php (thin shell)
  -> dispatcher::handle()   auth gate, protocol, privacy contract
  -> Moodle external functions (classes/external/*)
  -> facades: context_area, material_area, version_writer, catalog/*
  -> storage_port (Private Files | WebDAV)
  • Seam pattern: mcp.php only does input and output. Decisions are made in dispatcher, oauth_lib and instance_check as pure functions (values in, values out), testable without a web server.
  • Protocol: stateless, POST only, JSON. Served MCP revisions are 2025-06-18 (initialize handshake, e.g. Codex) and 2026-07-28 (server/discover, e.g. claude.ai).
  • Sign-in: OAuth 2.1 with PKCE, discovery (RFC 8414/9728), Dynamic Client Registration (RFC 7591) and CIMD. No manual token handling.
  • Writing: only through Moodle's form path (add_moduleinfo()/update_moduleinfo()) with a checked field catalog per activity type (ADR 0016/0017).
  • Change history: a full snapshot per write in a shadow table, including manual changes; restoring writes a new version (ADR 0018).
  • Storage: one anchor, one module, two adapters: the teacher's Private Files or WebDAV. If the storage fails, there's no fallback storage, only a pending note without content (ADR 0019–0023).
  • Skill corpus: the AI's way of working (plan, approve, carry out) ships with the plugin and is fetched through coursepilot_list_skills/coursepilot_get_skill, not installed (ADR 0020).

Not covered here: the earlier local setup (Node server on the laptop, Coursepilot 1.x) has been removed from the repository and is only reachable through the Git history.

Tool contract

  • One declaration per tool: tool_registry::TOOLS drives the web service registration (db/services.php), the MCP schema (derived from execute_parameters()) and the privacy allowlist. No second schema declaration.
  • English base: tool names, parameters, return keys and descriptions are English; Moodle strings live only in lang/en/ (ADR 0024).
  • Writing or reading follows from the naming pattern. Mutating tools use the pattern of a confirmation parameter (confirmed).
  • Contract tests: tool_schema_contract_test.php and privacy_surface_test.php check the surface actually registered.

Activity types

  • Cataloged (field catalog, create and edit): text and media area, page, URL, folder, file, choice, forum, assignment, quiz.
  • Derived (ADR 0028): any other installed type, create only. The activity XML is derived from an exported default, created hidden, exported again and compared; on a mismatch it's deleted in the same call. Changing means superseding: a new activity after the old one, the old one hidden.
  • Not via XML: types with questions (lesson; quiz goes through the catalog) and, for now, types with files in their content (SCORM, IMS content package, H5P, lightbox gallery).

Tests and CI

  • PHPUnit: full native suite in native-ci.yml, five combinations of Moodle 5.1/5.2/5.3, PHP 8.3/8.4, MariaDB 11.4 and PostgreSQL 17, plus fresh ZIP installation and an authorized tool call on all three Moodle lines.
  • Coverage gate: 80 % line coverage (PCOV, Moodle 5.1 run), source scope in tests/coverage.php.
  • Merge condition: only the aggregate check Gate (required); a skipped required job counts as a failure.
  • Node suite: npm run test:ci for helper scripts and this documentation site (links, image paths, language counterparts).

Contributing

  • Report bugs and suggestions as a GitHub issue; please open pull requests against dev.
  • Code language is English (identifiers, tool contract, lang/en/). Terms are in the glossary CONTEXT.md (German), decisions in docs/adr/, specifications in docs/specs/.
  • License: AGPL-3.0-or-later, the plugin included (ADR 0025). Contributions are under the same license.

Known limits

  • Beta: 2.1.2-beta, tried in the author's own teaching, not yet in production at another school. There are minor tool gaps in edge cases.
  • No rate limiting at the MCP endpoint. Protection so far comes from OAuth, per-person remote access and the kill switch.
  • Moodle plugins directory: submission is pending (#192); until then, the German translation ships inside the plugin instead of AMOS.
  • Change history isn't complete: quiz content beyond question order, the gradebook, restored backups and direct DB changes are missing; for derived types only the instance row, not the child tables (chapters, entries). Replaced activity files come back on a restore.
  • Derived activity types are only created or superseded, never edited; types with files in their content are still missing.
  • Tested environment covers five required combinations with PHP 8.3/8.4, MariaDB 11.4 and PostgreSQL 17. Other combinations are not implicitly verified.
  • Skill corpus German for now (#604).
